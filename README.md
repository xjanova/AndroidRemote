# AndroidRemote

รีโมทมือถือแอนดรอยด์จาก PC — คุมได้ตั้งแต่ระดับ `adb shell` ไปจนถึง `root`
ธีม Windows XP Luna "Silver" โลหะ 3 มิติ

## สแตก

| ชั้น | เทคโนโลยี | เหตุผล |
|---|---|---|
| ตัวแอป PC | Electron + TypeScript | ธีมเป็น HTML/CSS อยู่แล้ว · WebCodecs ถอดรหัส H.264/H.265 ด้วยฮาร์ดแวร์โดยไม่ต้องต่อ FFmpeg |
| หน้าจอ | TS ล้วน ไม่มีเฟรมเวิร์ก | ต้องวาดวิดีโอ 60–120 fps — virtual DOM มีแต่เสีย |
| คุย adb | socket ตรงไป `127.0.0.1:5037` | ได้ `track-devices` แบบ push · ไม่ต้อง spawn โพรเซสต่อคำสั่ง |
| ฝั่งมือถือ | Kotlin → dex → `app_process` | เขียนเอง เพื่อใส่ฟีเจอร์ระดับ root ได้ตามใจ |

## โครงไฟล์

```
src/
  shared/       ชนิดข้อมูลและสัญญา IPC ที่ทั้งสองฝั่งใช้ร่วมกัน
    types.ts      DeviceInfo, PrivilegeTier, ตาราง CAPABILITIES, Blocker
    api.ts        หน้าตา API ที่ preload วางบน window.androidRemote
  main/         โพรเซสหลัก (Node)
    adb/
      protocol.ts   ชั้นล่างสุด — framing ของโปรโตคอล adb บน socket
      AdbClient.ts  งานระดับ "ทำอะไรกับเครื่อง": exec, push, reverse, ไร้สาย
    device/
      probe.ts          ตรวจเครื่อง + หาระดับสิทธิ์ + สร้างรายการสิ่งที่ขวางอยู่
      DeviceRegistry.ts แหล่งความจริงเดียวว่าตอนนี้มีเครื่องอะไรอยู่
  preload/      สะพานเดียวที่ renderer มองเห็น main
  renderer/     หน้าจอ + ธีม XP Silver
server/         (ยังไม่เขียน) server ฝั่ง Android
design/         ม็อกอัปที่ใช้ตกลงหน้าตากันตอนแรก (.dc.html)
scripts/
  smoke-adb.ts  ทดสอบชั้น adb กับ adb server จริง
```

## ระดับสิทธิ์

แอปตรวจให้เองว่าเครื่องนี้ยิงคำสั่งได้ระดับไหน แล้วเปิด/ปิดฟีเจอร์ตามนั้น

| ระดับ | uid | ได้มายังไง | ปลดล็อกอะไร |
|---|---|---|---|
| `shell` | 2000 | เปิด USB debugging | มิเรอร์ · สั่งงาน · เสียง · คลิปบอร์ด · ไฟล์ · จัดการแอป · แก้ค่าระบบ |
| `shizuku` | 2000 | ผู้ใช้เปิดบริการ Shizuku ไว้ | เท่า shell แต่ไม่ต้องเสียบสายทุกครั้ง |
| `root` | 0 | `adb root` (ROM userdebug) หรือ `su` | สั่งงานตอนล็อกจอ · เขียน /dev/input ตรง · เข้าถึงข้อมูลแอปอื่น · ติดตั้งเป็นแอประบบ · คุมทุกโพรเซส · สลับ SELinux |

## สถานะตอนนี้

**ทำงานจริงแล้ว** — พิสูจน์ด้วยการรัน ไม่ใช่แค่คอมไพล์ผ่าน

- หา `adb.exe` เอง แล้วสตาร์ท adb server ให้ถ้ายังไม่ทำงาน
- คุยโปรโตคอล adb ผ่าน socket · เฝ้ารายชื่อเครื่องแบบ push
- ตรวจเครื่อง: รุ่น, ROM (HyperOS/One UI/ColorOS/LineageOS), จอ, แบต, ระดับสิทธิ์
- ตารางความสามารถ 14 อย่างที่คำนวณจากระดับสิทธิ์จริง + SDK ของเครื่อง
- การ์ดบอกสาเหตุที่ยังใช้ไม่ได้ พร้อมขั้นตอนแก้ทีละข้อ (รวมกับดัก Xiaomi)
- คู่มือเปิดโหมดนักพัฒนาบนหน้าจอเปล่า
- หน้าต่างไร้กรอบ วาดแถบหัวเอง + ธีม XP Silver ครบ

**เขียนครบแล้ว แต่ยังพิสูจน์กับเครื่องจริงไม่ได้** (ไม่มีมือถือเสียบตอนพัฒนา)

- `server/` ฝั่ง Android — จับภาพจอผ่าน SurfaceControl + MediaCodec, ยิง touch/key/scroll
  ผ่าน InputManager, ปิดจอมือถือขณะคุม, รันคำสั่งระดับ root แล้วส่งผลกลับ
  คอมไพล์เป็น dex สำเร็จ ครบ 15 คลาส (`npm run server:build`)
- ท่อวิดีโอ WebCodecs — ถอดรหัส Annex-B ด้วยฮาร์ดแวร์ วาดลงแคนวาส
- ส่งการสัมผัสจากแคนวาสกลับเข้าเครื่อง (แปลงพิกัดตามการย่อภาพให้แล้ว)

⚠ ทั้งหมดข้างบนยัง **ไม่เคยรันกับมือถือจริงสักครั้ง** — คอมไพล์ผ่านไม่ได้แปลว่าใช้ได้
เสียบเครื่องแล้วต้องไล่ทดสอบตามลำดับนี้ อย่าข้าม:

1. `npx tsx scripts/smoke-adb.ts` — พิสูจน์ `exec` / `push` / `reverse`
2. เปิดแอป เลือกเครื่อง กด "ลองยิงคำสั่ง" — พิสูจน์ช่องทางคุยกับเครื่อง
3. กด "เริ่มมิเรอร์" แล้วดูบันทึกเหตุการณ์ บรรทัด `[AR]` คือเสียงจาก server ฝั่งมือถือ
   - ถ้าค้างที่ "server ไม่ต่อกลับมา" → ดูว่า `[AR] E` ว่าอะไร มักเป็น SurfaceControl
   - ถ้าเห็นภาพแต่กดไม่ได้ → InputManager ถูกบล็อก (ดูกับดัก Xiaomi)

**ค้นหาบนวง Wi-Fi — ทำงานจริงแล้ว พิสูจน์ด้วยการรัน**

หาสามทางพร้อมกัน เพราะไม่มีทางไหนเห็นครบเอง:

| ทาง | เห็นอะไร |
|---|---|
| mDNS ที่เขียนเอง | แอนดรอยด์ 11+ ที่เปิดไร้สาย รวมทั้งเครื่องที่**กำลังเปิดหน้าจับคู่อยู่** |
| `adb mdns services` | สแตกของ adb เอง บางทีเห็นในสิ่งที่เรามองไม่เห็น และกลับกัน |
| กวาดพอร์ต 5555 | ทางเดียวที่เจอเครื่องซึ่งสั่ง `adb tcpip` เอง — พวกนี้**เงียบสนิทบน mDNS** |

- **เจอเครื่องที่เคยจับคู่ไว้ → ต่อให้เลย ไม่ต้องถาม** จำด้วย `ro.serialno` ไม่ใช่ IP
  (IP เปลี่ยนทุกครั้งที่ DHCP อยาก แต่ serial คงที่) เก็บลง `known-devices.json` ใน userData
- เปิดแอปมาลองต่อตามที่อยู่ล่าสุดทันที ไม่ต้องรอ mDNS เห็นก่อน
- ปิด "ต่ออัตโนมัติ" รายเครื่องได้ และลืมเครื่องได้

ผลทดสอบจริงบนเครื่องนี้: แกะแพ็กเก็ต mDNS ที่มีการบีบอัดชื่อผ่านครบ · กวาด 253 ที่อยู่ใน **1.3 วินาที**

```bash
npx tsx scripts/smoke-discovery.ts --sweep
```

**โหมดกล้อง — ใช้กล้องมือถือแทนเว็บแคม**

เส้นทางภาพเหมือนโหมดมิเรอร์ทุกประการ ต่างแค่ต้นทาง: กล้อง → Surface ของ MediaCodec → ซ็อกเก็ต

- เห็นกล้องทุกตัวที่เครื่องมี (หลัง อัลตร้าไวด์ เทเล หน้า) พร้อมความละเอียดสูงสุดของแต่ละตัว
- เลือกกี่ตัวก็ได้ — หนึ่งสตรีม หนึ่งซ็อกเก็ต หนึ่งเธรด ตัวหนึ่งพังไม่ลากตัวอื่นไปด้วย
- ⚠ เครื่องส่วนใหญ่เปิดกล้องหน้ากับหลังพร้อมกัน **ไม่ได้** เพราะแชร์ ISP ตัวเดียวกัน
  แอปอ่าน `getConcurrentCameraIds()` มาบอกตรงๆ ว่าชุดที่เลือกเครื่องนี้รับประกันหรือไม่
- ได้ Context โดยไม่เป็นแอปด้วย `ActivityThread.systemMain().getSystemContext()`

**โหมดจอยเกม — มือถือกลายเป็นจอย**

PC เปิดเว็บเซิร์ฟเวอร์ มือถือเปิดหน้านั้นในเบราว์เซอร์ **ไม่ต้องลงแอปอะไรบนมือถือ**
และใช้กับ iPhone หรือแท็บเล็ตเครื่องไหนก็ได้ ไม่ต้องพึ่ง adb เลย

- 14 ปุ่ม (ทิศทาง 4 · หลัก 4 · บ่า 4 · ระบบ 2) หลายนิ้วพร้อมกันได้
- ผูกปุ่มกับคีย์บอร์ดเองได้ทุกปุ่ม บันทึกลง `gamepad-keymap.json`
- ฉีดคีย์เข้า Windows ผ่าน exe 6.5 KB ที่คอมไพล์ด้วย `csc.exe` ซึ่งมีในวินโดวส์อยู่แล้ว
  **ส่งเป็น scan code ไม่ใช่ virtual key** เพราะเกมที่อ่านผ่าน DirectInput มองไม่เห็น virtual key
- WebSocket เขียนเอง (โปรเจคนี้ไม่มี runtime dependency สักตัว)

```bash
npm run native:build     # สร้าง server ฝั่ง Android + ตัวฉีดคีย์
npm run smoke:gamepad    # ทดสอบเซิร์ฟเวอร์จอย (ผ่านครบ 9 ข้อ)
npm run smoke:discovery  # ทดสอบการค้นหาบนวง LAN
```

**ยังไม่ได้ทำ**

- เสียง (AudioRecord บน REMOTE_SUBMIX)
- พิมพ์ข้อความ — ทางปัจจุบันผ่าน KeyCharacterMap ซึ่ง **พิมพ์ไทยไม่ได้**
  ต้องทำ UHID หรือ IME ของเราเองแทน
- ฟีเจอร์ระดับ root ที่เหลือ (uinput, เข้าถึงข้อมูลแอปอื่น, ติดตั้งเป็นแอประบบ)
- เมนูบาร์ยังเป็นของประดับ ยังไม่ผูกคำสั่ง
- ยังไม่ได้ตั้งค่า electron-builder สำหรับแพ็กแจก

## หมายเหตุการออกแบบ

- **ตรวจไม่ได้แน่ชัด ให้บอกว่าไม่แน่ใจ** ดีกว่าขึ้นเขียวแล้วผู้ใช้ไปเจอทีหลังว่ากดไม่ได้
  เช่น เครื่อง Xiaomi จะขึ้นเตือนเรื่องสวิตช์ security settings เสมอ เพราะตรวจตรงๆ ไม่ได้
- **แผงโลหะที่สูงเกิน 30px ต้องตรึงความสูงแสงสะท้อน** ด้วย `background-size` ไม่งั้นไล่เฉดยืดจนจืด
- **ลายบรัชต้องรู้สึกได้แต่ห้ามอ่านออกเป็นเส้น** ค่าที่สวยบนอาร์ตบอร์ดเล็กจะกลายเป็นทางม้าลายบนหน้าต่างจริง
